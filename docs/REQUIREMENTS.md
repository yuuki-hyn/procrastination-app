# 要件定義書

先延ばし解決webアプリ

## 1. 背景・原体験

私自身、先延ばしという課題を抱えており、その改善策を調査・実践する中で「タスク分割」という方法にたどり着いた。大きな課題を小さなタスクに分割することで、それぞれの小タスクに対して締切を設定し、完了時にチェックを付けて記録することが可能になる。

この一連の流れを実践した結果、これまで着手が遅れがちだった休日でも午前中から必要な作業に取り掛かれるようになり、一日あたりの作業時間が数倍に増加した。

この効果が生まれた要因として、以下の3点が考えられる。

1. **期待の向上**：タスクが小さく具体的になるほど、「これなら自分にもできる」という達成確率への自信が高まる
2. **遅れの短縮**：小タスク単位で締切を間近に設定できることで、「今取り掛からなければ間に合わない」と感じるタイミングを増やせる
3. **価値の即時化**：小タスクごとに達成できたかがすぐにわかるため、着手してすぐの段階から、達成感を繰り返し得られる

これは行動科学における先延ばし方程式（後述）の各項目に対応しており、本アプリはタスク分割を中核に据え、そこから派生する締切設定・完了記録の機能によってこの3つの要因に働きかける設計とする。

## 2. ターゲット・コンセプト

### ターゲット

本アプリが対象とするのは、**タスクが大きいことに起因して**、着手・継続のさまざまな場面で行動が止まってしまう人である。タスクの大きさは、単に「量が多くて大変」という直接的な負担だけでなく、以下の5つの形で間接的にも行動を妨げる。

1. **見通しの欠如**：タスクが大きいほど、完了までにやるべきことが多岐にわたるため、整理しないと道筋が見えない
2. **選択の多さによる迷い**：タスクが大きいほど、細かくやるべきことの選択肢が増え、「やることが多い」という負担と「何から始めればいいか分からない」という迷いの両方が着手を遅らせる
3. **最初の一歩の重さ**：タスクが大きいほど、それをやり切ることを想像したときの心理的な負担が大きくなり、着手そのものへの抵抗が強くなる
4. **期限の曖昧さ**：タスクが大きいほど、完了に必要な時間を見誤りやすく、また実際に時間もかかるため、期限を先延ばしに設定してしまい、「今すぐやらなければ」という意識につながらない
5. **達成感の欠如**：タスクが大きいほど、完了までに時間がかかるため、達成感を得られる機会がなかなか訪れない

つまり、タスクの大きさという単一の原因が、見通し・選択・着手・期限・達成感という5つの経路を通じて、複合的に行動を妨げている。

### 本ターゲット定義の位置づけ

上記のターゲット定義および要因分析は、現時点では自身1人の原体験（n=1）に基づく仮説である。タスク分割が効果を持った理由は自己分析によるものであり、他者にも同様に当てはまるかは検証されていない。

そのため本アプリはMVPをあくまで**仮説検証の第一段階**と位置づける。リリース後は、実際の利用データ（タスクの完了率、継続利用率など）や周囲へのヒアリングを通じて、ターゲット定義と機能の妥当性を継続的に見直す。

### コンセプト

本アプリは、**タスクを分割すること**を中核に据える。分割によってタスクの大きさそのものを解消することで、上記5つの派生的な問題すべてに同時にアプローチできる。

- 分割された小タスクの並びが完了までの道筋となり、見通しの欠如を解消する
- 画面には今取り組む小タスクと次の小タスクのみを表示し、選択の多さによる迷いを減らす
- 小タスクの最初の一歩をさらに30秒単位まで小さくすることで、着手の重さを最小化する
- 小タスク単位で締切を設定できるようにすることで、期限を先送りにする余地をなくす
- 小タスクごとに完了を記録できるようにすることで、達成感を得られる頻度を上げる

> **タスクを分割し、その大きさに起因する見通し・選択・着手・期限・達成感の5つの問題を同時に解消することで、先延ばしを減らすアプリ**

### 既存アプリとの違い

先延ばし対策・タスク管理を謳うアプリはすでに多く存在するが、それぞれ主眼を置く要因が異なる。

| アプリの傾向 | 主なアプローチ | 本アプリとの違い |
|---|---|---|
| Todoist等の汎用タスク管理アプリ | タスクの記録・締切管理そのものを支援 | 記録の網羅性を重視しており、タスクの大きさそのものへの介入は行わない。長期的な予定も自由に登録できるため、計画自体が負担になりうる |
| Forest等のモチベーション系アプリ | 集中時間の可視化やゲーミフィケーションで継続を促す | 価値（Value）を高める方向のアプローチが中心。本アプリはゲーミフィケーションを離脱リスクの観点からあえて採用していない |
| ポモドーロ系タイマーアプリ | 時間を区切って集中を促す | 「時間」の区切りに主眼があり、「タスクの大きさ」自体は分割しない。着手前の負担軽減には踏み込まない |

本アプリは、これらとは異なり、**先延ばしの根本原因をタスクの大きさに絞り、分割という単一の操作で複数の障壁（見通し・選択・着手・期限・達成感）に同時対処する**点で差別化される。またタスクを翌日までに限定することで、長期計画のツールと化すことを避け、「今日・明日を乗り切る」ことに特化している点も特徴である。

## 3. コア体験

大きなタスクを登録したら、ユーザー自身の手で小さなタスクへと分割する。分割した小タスクにはそれぞれ締切を設定でき、さらに着手のハードルを下げるための「30秒で終わる最初の一歩」も設定できる。

ホーム画面には、今取り組むべき小タスクと次の小タスクの2件だけが表示され、他のことを考えずに目の前の一歩に集中できる。小タスクが完了したらチェックを付けて記録し、その達成感をすぐに得られる。これを繰り返すことで、大きなタスクだったものが、気づけば着実に終わっている。

> **大きなタスクを自分の手で分割し、今やるべき一歩だけを示し、完了のたびに達成感を積み重ねることで、迷わず・止まらず前に進めるアプリ**

## 4. 理論的根拠：先延ばし方程式

本アプリの設計は、行動科学における先延ばし方程式（Piers Steel, 2007）を理論的根拠とする。

**モチベーション ＝ (期待 × 価値) ／ (衝動性 × 遅れ)**

- **期待（Expectancy）**：そのタスクを成功させられるという自信
- **価値（Value）**：タスクや、その先にある報酬の魅力
- **衝動性（Impulsiveness）**：目先の誘惑に流されやすい傾向
- **遅れ（Delay）**：タスクの完了や報酬を得られるまでの時間的な距離

自身の原体験を分析すると、特に**期待の低さ**と**遅れの大きさ**が先延ばしの主な原因だったと考えられる。一方、衝動性は自身の特性として強く自覚しているが、アプリの機能で直接コントロールすることは難しいと判断し、本アプリでは扱わない。代わりに、衝動性が発動するきっかけ（タスクの負の価値・着手の負担）自体を減らすことで、間接的に逃避行動の発生を抑える設計とする。

### 機能と方程式の対応

| 機能 | 効く項目 | メカニズム |
|---|---|---|
| タスク分割 | 期待↑ | タスクを小さく具体化することで、成功できるという自信を高める。タスクの大きさに起因する見通し・選択・着手・期限・達成感の問題を根本から緩和する |
| ホーム画面（今＋次の2件表示） | 期待↑ | 選択肢を絞ることで、何からやるかを判断する負荷を下げ、着手への自信を保つ |
| 30秒スタータータスク | 期待↑ | 「30秒ならほぼ確実にできる」という極めて高い成功見込みを作り、着手の心理的抵抗を最小化する |
| 締切設定 | 遅れ↓ | 完了までの時間的な距離を明確にし、「今やらなければ間に合わない」という意識を作る |
| 完了記録 | 価値↑ | 達成をすぐに確認できるようにすることで、タスクそのものの魅力（即時的な報酬）を高める |

## 5. 機能一覧（MVP）

### タスク分割

- 大きなタスクを登録できる
- 登録したタスクを、自分の手で複数の小タスクに分割できる（自動分割は行わない）
- 分割した小タスクの順番を、ワンタップで簡単に並び替えられる（上下ボタンによる入れ替え）

### タスク管理範囲の制限

- タスクは一日ごとに管理し、締切として設定できるのは**常に翌日まで**に制限する（休日前も例外なし）
- タスク一覧画面は「今日」「明日」の2タブ構成とし、大タスクを並べて表示する
- 各大タスクは矢印ボタンで小タスクを展開表示でき、タスク本体をタップすると小タスク追加・並び替え画面に遷移する

### 着手中の大タスク選択

- ユーザーは、複数登録した大タスクの中から、1つを「着手中」として指定できる
- 着手中に指定できる大タスクは、同時に1つだけとする
- ホーム画面には、着手中に指定された大タスクに紐づく小タスクのみが表示される

### ホーム画面（今やることへの集中）

- 全タスク一覧とは別に、今取り組むべき小タスクと次の小タスクの2件だけを表示する
- 目の前の一歩だけに集中できる画面構成とする

### 30秒スタータータスク

- 小タスクごとに「30秒で終わる最初の一歩」を設定できる
- 着手に迷ったとき、まずこの30秒タスクだけを確認して行動を始められる

### 所要時間の見積もり・実績記録

- 小タスク登録時に、所要時間の見積もりを任意で入力できる
- 小タスク完了後に、実際にかかった時間を任意で記録できる（完了操作はチェックのみで完結させ、実績時間は小タスク詳細の編集から記録する）
- 見積もりと実績の両方を記録することで、将来的に見積もり精度の傾向を可視化する土台とする（分析・表示機能自体はv2以降）

### 締切設定

- 分割した小タスクそれぞれに、今日〜翌日の範囲で締切を設定できる
- 締切が近い小タスクを認識し、着手の判断材料にできる

### 完了記録

- 完了した小タスクにチェックを付けて記録できる
- 記録した完了状況を振り返り、達成感を得られる

### 削除機能

- ユーザーは大タスクを削除できる。削除すると、配下の小タスクもすべて削除される
- ユーザーは小タスクを個別に削除できる

### 認証

- ユーザーはメールアドレスとパスワードでアカウントを作成できる
- ユーザーはメールアドレスとパスワードでログインできる
- ユーザーはログアウトできる
- ユーザーはパスワードを変更できる
- 認証にはJWTを用い、トークンは`httpOnly` Cookie（`SameSite`属性つき）で保持する。パスワードはハッシュ化して保存する

## 6. 見送った機能とその理由

| 機能 | 見送った理由 |
|---|---|
| 目的メモ（「これができたら〇〇できる」） | 価値を高める方向の機能であり、本アプリが主軸とする「タスクの大きさに起因する負担の軽減」という方針とは軸が異なるため見送り |
| 完了時のご褒美設定 | 目的メモと同様、価値の付加を狙う機能であり、負担軽減という中核方針から外れるため見送り |
| 開始予定時刻＋予備の開始時刻 | 締切設定と役割が重複する部分が大きく、MVPでは締切設定のみで検証を優先 |
| カテゴリ切り替え・目的外切り替えの検知 | 衝動性を直接検知・制御しようとする方向性であり、「衝動性は間接的にしか扱わない」という方針と矛盾するため見送り |
| 保留機能（理由記録つき） | カテゴリ切り替え検知と同様、衝動的な回避の検知・区別を目的とした機能であり、負担軽減という主軸から外れるため見送り |
| リマインド通知 | 実装コストに対してMVPの検証に必須ではないと判断。効果としてはホーム画面の表示制御や締切設定と重複する部分もある |
| 生産的な先延ばしモード | 保留機能を前提とした派生機能であり、保留機能自体を見送ったため連動して見送り |
| 今日のまとめ画面 | 完了記録による達成感の提供で一定の効果が見込めるため、追加のUIはMVPでは不要と判断 |
| ポイント／ストリーク／バッジ（ゲーミフィケーション） | 未達成が続いた際にアプリ利用そのものから離脱するリスクが高いと判断し、不採用 |
| 未完了タスクの自動繰り越し | 運用上あると便利だが、MVPの検証には直接関与しないため見送り |
| 週次振り返り画面 | 「振り返る」段階の機能全般は、MVPで着手・継続の効果を検証してから設計する方が精度が高いと判断し、v2以降に位置づける |

見送った機能の多くは、①本アプリの主軸（タスクの大きさに起因する負担の軽減）から外れる、②衝動性を直接制御しようとする方向性である、③MVPでの検証に必須ではない、のいずれかに該当する。いずれも意図的な除外であり、単なる後回しではない。

## 8. 画面構成・遷移

主要画面は以下の5つ。加えて、小タスク一覧画面の上にはモーダル（ボトムシート）として2種類の入力画面が重なる。

1. **ログイン画面**：メールアドレス・パスワードでの認証。新規アカウント作成画面と相互に遷移できる
2. **新規アカウント作成画面**：お名前・メールアドレス・パスワードでアカウントを作成し、作成後は自動的にログイン状態になる
3. **大タスク一覧画面**：今日／明日タブで大タスクを表示。今日タブのみ、各大タスクに「着手する」ボタンを設け、タップした大タスクを着手中に切り替える（明日タブにはこのボタンを表示しない。翌日にならないと着手できないため）。矢印ボタンで小タスクを展開、タスク本体タップで小タスク一覧画面へ。削除操作もここから行う。ホーム画面と相互に遷移する
4. **小タスク一覧画面**：小タスクの並び替え・削除。各小タスクをタップすると、この画面の上に「小タスク詳細」モーダルが重なって表示される。「小タスクを追加」ボタンをタップすると、同じくこの画面の上に「小タスク作成」モーダルが重なって表示される
5. **ホーム画面**：着手中の大タスクに紐づく、未完了の小タスクのうち今／次の2件のみ表示。大タスク一覧画面と相互に遷移する
6. **完了記録**：ホーム画面上でのチェック操作のみで完結する（実績時間は後から小タスク詳細で記録する）。完了すると次の小タスクが「今」に繰り上がる

**モーダル（小タスク一覧画面の上に表示）**

- **小タスク作成**：タスク名・期限時刻・30秒スタータータスク・所要時間見積もりを入力し、追加する
- **小タスク詳細**：タスク名・期限時刻・30秒スタータータスク・所要時間見積もり・実績時間の編集、削除

背景に小タスク一覧が透けて見える形式とすることで、どの画面から呼び出された操作かが視覚的に分かるようにしている。

ログイン・アカウント作成の成功後はホーム画面に遷移する。

**開発環境構築フェーズでの追加・変更**

- **画面下部固定のタブバー**：ホーム／大タスク一覧の移動はタブバーで行う（ログイン・新規登録画面では非表示）。小タスク一覧画面では、タブバーに加えて上部の「大タスク一覧へ戻る」も表示する
- **大タスク作成モーダル**：大タスク一覧の「新しいタスク」から開く。入力はタスク名のみで、日付は開いているタブ（今日／明日）から自動で決まる
- **ホームから小タスク詳細を開く**：ホーム画面のタスクをタップすると小タスク詳細モーダルが開く。モーダルは開いた画面（ホーム）の上に重ねて表示する

画面遷移とインタラクティブなモックアップは `mockup.html` を参照。
